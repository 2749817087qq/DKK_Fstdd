# FSTDD005: SCHEMA 里声明了 FOREIGN KEY，但连接从未开启 PRAGMA foreign_keys —— 约束形同虚设，脏数据静默写入

## 现象

子表的 task_id 声明了外键，但向不存在的父记录插入返回 201，
生成孤儿数据 —— 它在任何父视图下都看不到，等同于静默丢失。

## 根因

```python
# SCHEMA 常量里写了 —— 只在建表那一次执行时生效
SCHEMA = "PRAGMA foreign_keys=ON; CREATE TABLE ..."

def connect_db(path):
    conn = sqlite3.connect(path)
    conn.execute("PRAGMA busy_timeout=10000")
    # 缺：conn.execute("PRAGMA foreign_keys=ON")
    return conn
```

## 教训

**声明与实现必须一致**：SCHEMA 里写了 FK，读代码的人就会认为约束生效。
这种「看起来有保护、实际没有」比「明确没有保护」更危险 —— 它让人放松警惕。
