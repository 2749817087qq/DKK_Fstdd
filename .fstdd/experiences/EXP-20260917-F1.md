## 现象

法定源整体搬迁后，节点 `FSTDD006` 的两个平台配置里仍留着旧路径：

```
.codebuddy/<DOMAIN>.json:12  "command": "... \"<旧法定源>/upstream/bin/fstdd\" guard check ..."
.claude/<DOMAIN>.json:12     "command": "... \"<旧法定源>/upstream/bin/fstdd\" guard check ..."
```

该路径在搬迁后已不存在 ⇒ Guard 钩子失效，FSTDD 的「无 active change 不得改代码」
约束**静默消失**。

## 根因

见 frontmatter。要点：`init` 把法定源绝对路径烧进项目级钩子；
而搬迁时的重指向手段只覆盖宿主 skill 层，**不覆盖项目层**。

## 处理

1. 定向排查（**必须含隐藏目录**）：
   对项目逐个 grep `.codebuddy` / `.claude`，而不是对整个项目递归
   —— 递归会扫到法定源本体（含 `.git`），既慢又易被信号打断。
2. 修复：把两份 settings 文件里的路径改为新法定源位置。
3. 复核：两份文件旧路径归零、新路径各 1 处；并确认新路径下的 CLI 确实存在、
   其 `guard` 子命令可用。
4. 顺带发现：同一节点内另有一处空壳目录（只剩 git 模板文件，无 HEAD/objects/refs），
   已移入备份。**其成因未能确证** —— 隔离实验证明 `git bundle verify` 与 `git status`
   在非仓库目录都不会创建 `.git`，故不归因于本规程的任一命令。

## 性质

流程覆盖缺陷（重指向范围不完整），非环境问题。
可复现、可 grep 检出、有明确修复手段。
影响面：**所有在法定源搬迁前就已初始化过的 FSTDD 项目**，且失效是静默的。
