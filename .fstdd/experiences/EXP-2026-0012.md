# EXP-2026-0012 NaN 序列化 500：崩点在响应 wrapper 而非端点，清洗守卫会被提前 return 绕过

## 现象
/api/backtest/run 对 REITs 策略 100% 返回 500（空体）。export 端点（同样调 run_backtest，返回 xlsx 二进制）却正常。日志：`ValueError: Out of range float values are not JSON compliant: nan`，栈顶在 `middleware/response_wrapper.py:69 JSONResponse(content=data)`。

## 修复路径（两次才修对）
1. 第一次：在 `services/backtest_service.py::_sanitize_numpy` **末尾**加 NaN→None——无效。因为 `isinstance(obj,(np.floating,)): return float(obj)` 分支**提前 return**，np.float64(nan) 根本走不到末尾（np.float64 是 float 子类）。
2. 第二次：把 np.floating 与 python float 合并到一个分支，转换后立即判 NaN——service 层干净了，**仍 500**。
3. 第三次：traceback 定位真正崩点在全局 `response_wrapper.py`——端点层序列化容忍 NaN 字面量，wrapper json.loads 后用 starlette JSONResponse（allow_nan=False）重渲染才炸。在 wrapper 的 json.loads 后统一 `_strip_nan` 后修复。

## 教训
- "500 且日志是 not JSON compliant" 时先看**最终渲染层**（全局 wrapper），不是业务层；
- 给"多分支提前 return 的清洗函数"加新守卫时，守卫必须放在**所有 return 路径的汇聚点**，或重构分支合并处理；
- 二进制端点正常 + JSON 端点 500 = NaN 序列化问题的指纹。
