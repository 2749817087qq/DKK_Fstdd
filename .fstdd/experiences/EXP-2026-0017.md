# 出站路径未统一收口：脱敏在上游、发送在下游直读源目录

## 现象

`tools/share_experience.py` 的脱敏只发生在「导出写盘」（`prepare_entries()` → `experiences/`）。
四条出站路径（scp / GitHub 直推 / GitHub fork+PR / inbox POST）在发送时**默认源目录已干净**，
直接读取 `experiences/` 原始文件外发。

一旦 `experiences/` 混入未经本流水线的文件（手工放入的 `EXP-*.md`），
其中的绝对路径与凭证片段就被原样发出。实测事故：某经验含 `/home/ubuntu/...` 与一段 token，
被接收端以 `contains POSIX home path` 拒收。

## 为什么危险

出站是**离开本机**的动作，方向不可逆 —— 漏脱敏可补救，误脱敏或已外发不可逆。
把「源目录干净」当作不变量，等于把安全性寄托在「没有旁路写入」这一无法保证的假设上。

## 更一般的形态

- 同一份安全处理被多个出口共享时，收口点必须放在**出口侧**（数据离开边界的那一刻），
  而不是上游（假设数据已就绪）。
- 若存在绕过主调度函数的**直接调用**（如 silent 入口直调底层发送函数），
  只在主函数收口会留下旁路 —— 收口点要下沉到每个真正外发的函数入口。
- 第二道防线（残余自检）容易被上层拦住后变得不可观测，需把判据抽为可断言常量。
