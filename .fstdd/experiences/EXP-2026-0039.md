## 实测受影响点（4 处，全部为 EXP- 前缀假设）

| 位置 | 症状 |
|---|---|
| `tools/share_experience.py` `collect_local()` | 回传通道漏推所有新经验（最严重） |
| `tools/fstdd003_daily_share.py` `main()` | 每日分享漏推 |
| `tools/audit_experience_baseline.py` `INDEX_ITEM_RE` | 只允许一段前缀，新 ID 命中 0 条 → 全量误判「未入索引」 |
| `upstream/.fstdd/hooks/session-end.py` | 计数偏低（仅提示文案） |

## 关键点

FSD-004 门禁当时只扫 `fstdd/cli`，所以这 4 处「已修过一次的同一类 bug」在包外复活。
**门禁范围 = 真实的攻击面，不是包边界。**

## 另一层：段数漂移

ID 里含分隔符时，`split('-')[-1]` 取序号的假设会被打穿
（`MY-P-0803ADF7` 三段 → `_rebuild_index` 把 HEX 段 `0803ADF7` 当序号，`last_id` 跳到 803 万级）。
格式约束必须保证「段数恒定」，否则下游所有按段解析的地方都要重审。
