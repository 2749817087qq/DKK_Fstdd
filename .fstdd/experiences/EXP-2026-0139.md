# 症状

在 `*.service.d/override.conf` 中写 `StartLimitIntervalSec=300` 到 `[Service]` 段，
或把 `OnFailure=` 写在 `[Service]` 段 —— systemd **不报错、不失败**，
只在 journal 打一行 warning 后**静默忽略**：

```
override.conf:10: Unknown key name 'StartLimitIntervalSec' in section 'Service', ignoring.
```

# 为什么危险

1. **`systemctl show` 会给出「已生效」假象**：若你写的值与默认值**巧合相同**
   （如 `StartLimitBurst=5` 恰为默认），`show` 显示 `5`，看起来生效，实际 `StartLimitIntervalSec=300`
   被丢弃、仍是默认 `10s` ⇒ 实际限流与设计意图相差 30 倍。
2. **`OnFailure=` 写错段 ⇒ 告警链路整体静默失效**（失败时不会触发任何告警）。
3. 只有 `journalctl` 里一行 `Unknown key name ... in section ... ignoring` 是唯一线索。

# 正确段落（systemd ≥ 229）

| 指令 | 正确段落 |
|---|---|
| `StartLimitIntervalSec` / `StartLimitBurst` | **`[Unit]`** |
| `OnFailure` / `After` / `Description` | **`[Unit]`** |
| `Restart` / `RestartSec` / `RestartPreventExitStatus` | `[Service]` |
| `Type` / `User` / `ExecStart` | `[Service]` |

# 检出方法（必须做）

1. 写完 drop-in 后 **必看 journal**：`sudo journalctl --since '2 min ago' | grep -i 'Unknown key name'`
2. **不要只信 `systemctl show` 的字面值** —— 用「与默认值不同的值」做断言
   （例：断言 `StartLimitIntervalUSec=5min` 而非 `StartLimitBurst=5`）
3. 对 `OnFailure`：断言展开非空且有实例名，`systemctl show <unit> -p OnFailure`

# 教训

**「配置写了」≠「配置生效」**。systemd 对未知键的宽容（只 warning）使得段落错误成为静默失效家族；
凡「改了但行为没变」，第一嫌疑是段落/键名，第二证据是 journal 的 `Unknown key name`。
