# 症状

轮换数据库口令后，逐文件检查显示「4 个文件、每个替换 1 处」全部成功，md5 也都变了。
但收尾时用 `set -a; . <file>; psql "$DATABASE_URL"` 验证，其中一个文件报：

```
psql: error: connection to server on socket "/var/run/postgresql/.s.PGSQL.5432" failed:
FATAL:  role "root" does not exist
```

排查后发现：该文件的 `DATABASE_URL` 是 **`postgresql+asyncpg://`** 形态，
替换模式只匹配裸 `postgresql://` ⇒ **这个字段的口令压根没被改**，仍是旧口令。
（同文件里另一个字段是裸形态，所以替换计数=1、md5 变化，掩盖了漏改。）

# 为什么危险

1. **静默漏改**：替换数与 md5 都「看起来正常」，没有报错。
2. **旧凭据残留**：漏改的字段继续持有效旧口令 ⇒ 轮换目的（销毁已泄露口令）**未达成**。
3. **误判方向**：`psql` 报 `role "root" does not exist` 会把人引向「文件权限/内容损坏」，
   而真因是「校验工具不支持的 URI 方言」。

# 正确做法

1. **替换模式双形态**：`postgresql(?:\+[a-z0-9_]+)?://` 或分两条正则都跑一遍。
2. **收尾全量形态扫描**（唯一可信判据）：
   对每个候选文件里**每一处** DSN 取口令段，与旧/新口令比对（只输出 SAME/NEW，不打印口令），
   **断言 `SAME` 残留 == 0**。本次即靠此判据发现 `/opt/ccreits/rsds/.env` 仍有 1 处 SAME。
3. **校验工具要匹配**：验证方言 DSN 不能用 `psql`；要么把 `+<dialect>` 去掉转成 libpq 形态，
   要么用对应 driver（本例可用 psql 验证同文件的裸形态字段）。
