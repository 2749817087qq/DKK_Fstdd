## 现象

本节点开发环境快照（2026-09-18 13:48 采集，全部为只读命令实测值，非估算）：

| 项 | 实测值 |
|---|---|
| 操作系统 | Windows 11 专业版 64 位（Build 10.0.22621） |
| CPU | Intel Pentium Gold G5400 @ 3.70GHz，2 核 / 4 逻辑处理器 |
| 内存 | 16 GB 总量，可用约 6 GB |
| Python | managed 3.13.12（无 pytest）+ venv `default`（pytest 9.1.1） |
| 磁盘 C 盘 | 220.2 GB 总量 / 106.9 GB 可用 |
| 磁盘 D 盘 | 245.6 GB 总量 / 114.7 GB 可用 |
| 磁盘 E 盘 | 111.7 GB 总量 / 110.7 GB 可用 |
| 回传通道 | 官方 8787 端口可达，`/health` 返回 received 计数 |
| PyPI | 可达，`pip download six` 实测 10 秒完成 |
| GitHub | 443 端口本环境不可达（与 STATUS-1 一致） |

## 根因

不适用，基线快照。

## 检测触发

复查本机配置可重跑以下只读命令序列：

- `wmic os get Caption,Version,OSArchitecture`（系统与位数）
- `wmic cpu get Name,NumberOfCores,NumberOfLogicalProcessors`（CPU 拓扑）
- `wmic os get TotalVisibleMemorySize,FreePhysicalMemory`（内存，单位 KB）
- `wmic logicaldisk get DeviceID,Size,FreeSpace`（磁盘，单位字节，需除 1024³ 换算 GB）
- `python -m pip download --no-deps -d <tmp> six`（验证 PyPI 可达，仅下载不安装，避免污染现有 venv）
- `curl <回传服务器>/health`（验证通道存活并读取 received 计数）

触发条件：官方下发算力/任务分配需求，或本节点需判断能否承接重计算类任务时。

## 修复模板

不适用。维护建议如下：

1. **测试环境约定**：managed python 3.13.12 未预装 pytest，`cd upstream && python -m pytest tests -q`
   会直接报 `No module named pytest`。正确入口是使用已装 pytest 的 venv
   `default` 的 python 解释器，而非裸 `python`。
2. **CPU 算力约束**：2 核 / 4 逻辑的低配 CPU 上，全量测试套件 503 个用例
   实测需 138 秒。若官方要求"60 秒内给出 N passed"，需在回执中如实说明
   覆盖率上限（本机 60 秒约覆盖 72%），不要为凑数截断后谎报通过。
3. **只读纪律**：pytest 跑测试时建议追加 `-p no:cacheprovider`，避免
   在本项目工作区写入 `.pytest_cache`，保持盘点类任务的只读承诺。
4. **磁盘余量**：D 盘可用 114.7 GB 为主要工作区盘，E 盘近乎写满
   （仅 1.4 GB 余量），新数据资产不应默认落 E 盘。
