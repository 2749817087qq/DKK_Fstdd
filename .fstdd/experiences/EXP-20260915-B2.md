## 现象

把数据目录 `.stdd/` 改名为 `.fstdd/` 时：

- 替换脚本改了 **319 个文件、2205 处引用**（代码里都指向 `.fstdd`）
- 根目录的 `.stdd/` 也用 `git mv` 改成了 `.fstdd/`
- 但安装时出现：

```
[SKIP] 源文件不存在: .../upstream/.fstdd/skills/deliver.md
[SKIP] 源文件不存在: .../upstream/.fstdd/skills/upgrade.md
```

**6 个 skill 只装成功 1 个，其余静默跳过。**

## 根因

`upstream/` 下还有一个**同名的** `.stdd/` 目录，我只改了仓库根那个。

于是：
- 代码引用：`SRC/".fstdd"/"skills"`（已改）
- 磁盘实体：`upstream/.stdd/skills`（没改）

引用与实体错配。

## 处理

```bash
# 先枚举所有同名目录，再逐个决策
find . -type d -name ".stdd" -not -path "./.git/*"
```

结果发现 11 个（含 `backup/*/.stdd` 历史快照、`_bootcamp/*/work/.stdd` 示例）。
决策：改 `upstream/.stdd`，**保留** `backup/*/.stdd`（历史快照，改了破坏备份语义）。

## 一般化

**"改了引用"不等于"改了实体"**，反之亦然。迁移类任务必须双向核对：

| 方向 | 检查手段 |
|---|---|
| 引用 → 实体 | 引用路径是否真实存在 |
| 实体 → 引用 | 磁盘上是否还有旧名残留 |

另外注意：**静默跳过比报错更危险**。本例中 install 脚本对缺失源文件只打 `[SKIP]`
就继续，最终"成功退出"但只装了一个 skill —— 若没有断言核对数量，就会误判为成功。
