# 症状（一个会得出错误结论的假绿）

验证 `Restart=on-failure` 自愈时，用 `kill -TERM <postmaster_pid>` 制造「故障」，
然后看到：
- `is-active` = `active`
- `NRestarts` **仍为 0**
- `MainPID` **与 kill 前相同**

⇒ 容易误读为「自愈成功」或「kill 没生效」。**两者都不对。**

# 真实机理

| 信号 | 目标进程行为 | 退出码 | 在 `Restart=on-failure` + `RestartPreventExitStatus=0` 下 |
|---|---|---|---|
| `SIGTERM` | postgres 走 **smart shutdown**（正常关闭） | **0** | **不重启**（被 `RestartPreventExitStatus=0` 正确拦截） |
| `SIGKILL` | 立即终止，无法清理 | 非 0（被信号杀死） | **自动重启**（`on-failure` 生效） |

⇒ `kill -TERM` 实际验证的是「**运维可停**」这条路径（与 `systemctl stop` 同效果），
**不是**「故障自愈」路径。

# 正确验证方法（两条路径必须分别做）

```bash
# 路径①：运维 stop / SIGTERM → 应【不】重启
sudo systemctl stop <unit>; sleep 12; systemctl is-active <unit>   # 期望 inactive
systemctl show <unit> -p NRestarts                                  # 期望 不变
sudo systemctl start <unit>

# 路径②：非正常退出（SIGKILL）→ 应【自动】重启
PID=$(systemctl show <unit> -p MainPID --value)
sudo kill -KILL "$PID"          # 必须用 KILL，且用【正数 PID】而非负 PID（进程组）
sleep 30
systemctl is-active <unit>                          # 期望 active
systemctl show <unit> -p NRestarts                  # 期望 +1（铁证「真的重启过」）
systemctl show <unit> -p MainPID                    # 期望 与 kill 前不同（换了新进程）
systemctl show <unit> -p ActiveEnterTimestamp       # 期望 为本次重启时刻
```

# 判据要点

- **`NRestarts` 递增是「真的重启过」的唯一硬证据**；`is-active=active` 单独不可信
  （进程可能压根没被杀掉）。
- **`MainPID` 变化**是第二重证据。
- 若 `NRestarts` 与 `MainPID` 均未变 ⇒ 该次「故障」没有真正发生 ⇒ 判据 FAIL（禁止判为通过）。
- 参照 EXP-2026-0132：oracle（这里 = `NRestarts`/`MainPID`/journal）必须独立于被测行为。

# 教训

**「看起来是 active」≠「自愈发生了」**。验证恢复类策略时，必须
(a) 先确认「故障真的制造出来了」，(b) 再确认「恢复真的发生了」，两者各有独立判据。
信号选择错误会让整个验证结论反向。
