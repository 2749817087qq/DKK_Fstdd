## 现象

macOS 上用 venv（Python 3.13.12 + PyYAML + Jinja2）执行一键安装：

```
[3/4] 生成 skill        → 7 个 skill 全部 [OK]，安全策略 [PASS]
[4/4] 校验
  [FAIL] CLI 冒烟：`fstdd init` 退出码 1：ModuleNotFoundError: No module named 'requests'
```

skill 文件已生成完毕，但 CLI 端到端冒烟失败，verify 退出码 1，整体安装判定为 FAIL。

## 根因

| 声明位置 | 列出的依赖 | 实际运行需要 |
|---|---|---|
| README「前置要求」 | PyYAML、Jinja2 | + requests |
| install.sh [2/4] 检查 | PyYAML、Jinja2 | + requests |
| install_workbuddy_skills.py `_check_runtime_deps` | PyYAML、Jinja2 | + requests |

上游 CLI 的 experience 拉取子模块在文件顶部直接 `import requests`（非函数内懒加载），
所以 `fstdd init` 一启动就触发导入，缺则立即崩溃。

## 修复

补装到同一 venv 后重跑 verify（注意 verify 脚本本身也要用该 venv 解释器执行，否则
`import yaml` 会因 system python 缺依赖而误判 FAIL）：

```bash
VENV/bin/pip install requests
VENV/bin/python tools/verify_workbuddy_skills.py   # 用 venv python，不是裸 python
```

通过后全部 [PASS]。

## 建议（上游/本仓库）

install.sh 与 install_workbuddy_skills.py 的依赖声明应补上 `requests`，
否则一键安装的「依赖检查 → 生成 → 校验」闭环会在最后一步断裂。
