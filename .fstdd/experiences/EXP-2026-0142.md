# 症状

对一个**正在被守护进程追加写入**的日志做「就地脱敏」后：

- 文件权限、属主、大小看起来都正常；
- 但**日志不再增长**（`ls -l` 长时间不变），而磁盘占用照涨；
- 或文件里出现一段 **NUL 字节**（`\0`）的空洞，`grep` 报 "binary file matches"。

# 为什么危险

1. **静默**：没有任何报错，只有「日志不再更新」这一现象 —— 而日志恰恰是排障时最先看的东西，
   它消失后**下一次故障将无从定位**（缺失的日志比异常的日志更致命）。
2. **不可逆**：inode 被 unlink 期间写者写入的内容，事后无法找回。
3. **判据假绿**：只检查「文件存在 + 权限对 + 能读到内容」会全绿 —— 因为文件确实在、内容确实是脱敏后的内容，
   只是**新日志再也进不去**。

# 正确做法

1. **等长替换**：口令段 → 同长度 `*`（`re.sub` 回调里用 `b"*" * len(m.group(2))`）。长度不变是安全的前提。
2. **保 inode 就地覆写**：`open(path, "r+b")` → `read()` → `seek(0)` → `write()` → `flush()` → `fsync()`；
   **不要 truncate**（等长无需）。
3. **写后三判据**（必须实测，不许声称）：
   - `normalize(before) == normalize(after)`；
   - `st_ino` 前后一致；
   - 触发一条新写入 → 文件确实增长 + `NUL 空洞 == 0`。
4. 若不能等长（例如必须替换成 `<REDACTED>` 这种语义化标记）⇒ 改为**先轮转再离线处理**：
   用 logrotate（带 postrotate HUP）把活跃文件转走，再离线改归档 —— 但要注意这样会让
   「当前文件」变成空文件，使「当前文件无明文」这类断言**退化为恒真**（vacuously true），须另设判据。
