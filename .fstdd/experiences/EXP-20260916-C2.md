## 现象

升级前检查发现系统里存在旧版 FSTDD（name: stdd）：

```
~/.workbuddy-ai/skills/stdd/   ← 2026-09-12 装的旧版
  SKILL.md (name: stdd, stdd_version 3.0.5)
  references/
  scaffold/
```

但 WorkBuddy 的可用 skill 列表中从未出现 stdd/fstdd 相关条目，
即旧版虽然「装了」但从未被加载，等于白装，且整个过程没有任何告警。

## 根因

| 目录 | WorkBuddy 是否加载 |
|---|---|
| `~/.workbuddy/skills/` | ✅ 实际加载 |
| `~/.codebuddy/skills/` | ✅ 实际加载 |
| 项目级 `.codebuddy/skills/` | ✅ 实际加载 |
| `~/.workbuddy-ai/skills/` | ❌ 内核不识别（0 引用） |

旧版安装脚本默认 OUT 写成 `~/.workbuddy-ai/skills`，文件落盘正常，
但内核根本不扫这个目录，于是静默失效。

## 修复

```bash
# 1. 卸载旧版（入废纸篓，遵循不硬删原则）
trash ~/.workbuddy-ai/skills/stdd

# 2. 新版 install 脚本默认 OUT 已修正为 ~/.workbuddy/skills
FSTDD_PY=<venv>/bin/python ./install.sh

# 3. 重启 WorkBuddy 或执行 /reload
```

新版 install_workbuddy_skills.py 已把默认 OUT 改为
`<DOMAIN>() / ".workbuddy" / "skills"`，并在注释中写明实测依据。
