## 已修复（本机已改，建议合入）

### P1 `install.sh` 的 `--py <path>` 参数解析失效
**现象**：`install.sh --yes --py /path/to/python` 报
`[1/4] Python: --py` → `line 57: --py: command not found`

**根因**：`for arg in "$@"` 的迭代列表在展开时已固定，循环体内 `shift` 不会让
下一次迭代跳过已消费的参数，于是 `PY="${1:-}"` 取到的是 `--py` 自身。

```bash
# 修复前
for arg in "$@"; do
  case "$arg" in
    --py) shift; PY="${1:-}" ;;   # ← 拿到的还是 "--py"
  esac
done

# 修复后：改用下标遍历
_args=("$@"); _i=0
while [[ $_i -lt ${#_args[@]} ]]; do
  case "${_args[$_i]}" in
    --py) _i=$((_i + 1)); PY="${_args[$_i]:-}" ;;
    --py=*) PY="${_args[$_i]#*=}" ;;
  esac
  _i=$((_i + 1))
done
```
注：`--py=/path` 形式原本正常，只有空格形式有问题。

### P2 `install.sh` 未把 `FSTDD_OUT` / `FSTDD_SRC` 传给 Python
**现象**：脚本头部注释声明支持 `FSTDD_OUT` 环境变量，最后也 echo
`skill 目录: $HOME/.workbuddy-ai/skills`，但 skill 实际写到了 `$HOME/.workbuddy/skills`
（Python 脚本自己的默认值），装完在 WorkBuddy 里不生效。

**根因**：只有 `export` 才会传给子进程；脚本里只做了 `${FSTDD_OUT:-...}` 展开用于显示。

```bash
export FSTDD_OUT="$(_winpath "${FSTDD_OUT:-$HOME/.workbuddy-ai/skills}")"
export FSTDD_SRC="$(_winpath "${FSTDD_SRC:-$SCRIPT_DIR/upstream}")"
```

### P3 Git Bash 路径未转 Windows 形式 → 写到 `<PATH><用户目录>/...`
**现象**：把 `FSTDD_OUT=/c<用户目录>/<用户>/.workbuddy-ai/skills` 传给 Windows Python，
文件被写到 `<PATH><用户目录>/<用户>\.workbuddy-ai\skills\`（盘符丢失，多出一层 `c\`）。

**根因**：Git Bash 的 `$HOME` 是 `/c<用户目录>/xxx`，Windows Python 的 `Path()` 把
`/c/...` 当成根目录下的相对路径。

**修复**：传给 Python 前统一过 `cygpath -m`（脚本里已有 `_winpath()`，调用时漏用）。

### P4 安装结束 echo 的目录与实际写入目录不一致
脚本末尾写死 `$HOME/.workbuddy-ai/skills`，实际按 Python 默认值走了 `$HOME/.workbuddy/skills`，
误导排查。已改为 echo 真实变量 `$FSTDD_OUT`。

## 待修复（未改）

### P5 `tools/setup_git_credential.py` 的 token 路径算错
```python
REPO = Path(__file__).resolve().<DOMAIN>        # = <仓库根>
TOKEN_FILE = <DOMAIN> / ".workbuddy-ai" / "tmp" / ".gh_token"
```
当仓库位于 `$HOME/.workbuddy-ai/FSTDD` 时，`<DOMAIN>` 已是 `$HOME/.workbuddy-ai`，
再拼一层得到 `$HOME/.workbuddy-ai/.workbuddy-ai/tmp/.gh_token`（实际不存在）。
实际应为 `$HOME/.workbuddy-ai/tmp/.gh_token`，建议直接 `<DOMAIN>() / ".workbuddy-ai" / "tmp" / ".gh_token"`（保留 `FSTDD_TOKEN` 环境变量覆盖）。

### P8 change 名称不支持中文
`fstdd new 测试变更-速率限制` 直接报"无效的 change 名称"。
正则只允许 ASCII 字母数字开头。中文用户高频踩坑，建议：
- 要么放宽到 Unicode 字母（`<DOMAIN>()`），
- 要么在报错里给出"检测到非 ASCII 字符，建议改用 <拼音/英文> xxx"的提示。

### P9 子命令缺少参数时的提示不友好
- `fstdd gate` → `Unknown subcommand: None. Use: approve`
- `fstdd gate approve` → `the following arguments are required: --gate, --confirmed-by`
  （正确用法：`fstdd gate approve --gate 1 --confirmed-by dialog`）
- `fstdd archive` → `the following arguments are required: name`

建议：无参/缺参时直接打印用法示例，而不是抛 argparse 的错误行。

### P10 Spec 的 GIVEN/WHEN 必须加粗写，否则解析为 0 且报错不提示格式
模板要求 `- **GIVEN** <前置条件>`（**加粗**）。若写成 `- GIVEN xxx`（不加粗），
`validate` 会报 `spec.md: GIVEN 数量 (0) 少于 Scenario 数量 (1)`，
但**不会提示是格式问题**，排查成本高。

同类：`test-plan.md` 的 TC 计数也依赖特定格式（`- TC-001` 之类），
本次写的 `# 测试方案 / ## TC-001 ...` 被计为 0 条。

建议：validate 在计数为 0 时追加一句"若已编写，请确认使用 `- **GIVEN**` / `- TC-xxx` 格式"。

### P11 Gate 3 在 Gate 2 确认后似乎被自动确认
测试中仅执行了 `gate approve --gate 2`，随后 `gate approve --gate 3`
返回 `Gate 3 already confirmed at <时间>`。若非预期，会绕过 Gate 3 这道质量门。

### ✅ 机制定论（2026-09-16 二次实证，取代此前"两个目录都会被扫描"的说法）

**加载目录 = 实例自己的 home 下的 `skills/`，是按 home 拼装的相对路径，不是写死的固定目录。**

`cli/dist/codebuddy.js` 中 `skills` 与 `agents / commands / hooks / output-styles / bin`
同属**一组相对目录名**被遍历拼接 —— 这解释了为什么该文件里 `.workbuddy-ai` 字面量是 0 次，
却仍能加载 `$HOME/.workbuddy-ai/skills`：**基址不是字面量。**

本机并存**两套 WorkBuddy 实例 home**（均已实证，各自带完整 `app/`）：

| 实例 home | 标志性内容 | 其 skills 目录 | 谁在加载 |
|---|---|---|---|
| `$HOME/.workbuddy` | `app/`（Crashpad、app-config.json、electron-log-preload.js） | `$HOME/.workbuddy/skills` | **本实例**（当前会话技能列表中的 `fstdd-*` 均定位在此） |
| `$HOME/.workbuddy-ai` | `app/`、`logs/`、`local_storage/`、`file-history/` | `$HOME/.workbuddy-ai/skills` | **另一实例**（`install-github-skill`、`stdd-hardening` 仅此处有） |

**因此"两个目录都会被扫描"的说法也不准确**：不是同一实例同时扫两处，而是
**两个实例各扫各的 home**。原观察（`.workbuddy-ai/skills` 的技能出现在"WorkBuddy 当前会话列表"）
成立，但那个会话属于**另一实例**，不是本实例。

**install 脚本默认值**：给定 FSTDD 的日常使用实例 home 为 `$HOME/.workbuddy`，
默认取 `$HOME/.workbuddy/skills` 正确（`install_workbuddy_skills.py` 现状），
另一实例用 `FSTDD_OUT` 覆盖。**不采纳"默认 `.workbuddy-ai`"的建议** —— 那会把默认值指向非日常实例。
