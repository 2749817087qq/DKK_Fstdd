# FSTDD005: 同步/镜像类钩子失败时 exit 0 且不上报告警 —— push 报成功，失败静默腐烂，直到有人偶然查看日志才发现

## 现象

新仓库的 post-receive 镜像钩子只有一行 echo 后 exit 0。
同项目的老仓库钩子却有三件套：故障标记文件 + 上报告警 + timeout 守卫。
新钩子是**相对现有标准的退版**，而退版没有任何告警。

日志里明文记录了一次真实失败（权限问题，rc=128），三小时后人工换凭据才成功。
期间 push 一直报成功，控制面毫不知情。

## 为什么危险

这类失败的方向是**单向恶化**：不会自己恢复，也不会报错，只会让镜像越来越旧。
一旦进入「多个 agent 自动执行」模式，没有人盯日志，腐烂就是永久的。

## 更一般的形态

「为了不阻断主流程而 exit 0」是正确的；
错误的是把 exit 0 等同于「当没事发生」。**不阻断 =/= 不记录 =/= 不上报**，三者要分开处理。
