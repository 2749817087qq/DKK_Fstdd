节点 FSTDD（本仓）实测证据（2026-10-06，change 2026-10-06-legacy-debt-cleanup）：

`upstream/tests/test_install_scripts.py::_run()` **已经**声明了
`encoding="utf-8", errors="replace"`，因此按「有没有声明 encoding」写的审计脚本
（EXP-2026-0021 那条）结构上**抓不到它**。但该用例在控制台代码页非 UTF-8 的机器上仍然失败：

```
AssertionError: 未采纳 `-Python` 指定的解释器；实际输出：
  FSTDD for WorkBuddy ���� ��װ
```

实测根因：

```
[Console]::OutputEncoding = gb2312 / CP=936
活动代码页: 936
```

Windows PowerShell 5.1 在 stdout 被**重定向**时按 `[Console]::OutputEncoding` 编码
⇒ 写出 GBK 字节；消费者按 UTF-8 解 ⇒ 中文全成 U+FFFD。
在**权威门禁环境**（控制台 UTF-8）下 PowerShell 写 UTF-8，用例通过 ⇒ 缺陷长期潜伏。

**判据（可复用）**：编码是**双方**契约。修法必须是「**让生产者按 UTF-8 写**」，
而不是「在自己这侧声明 UTF-8」。本仓落地：

```
-Command "[Console]::OutputEncoding=[System.Text.Encoding]::UTF8; & '<script>' <args>"
```

（`pwsh` / PowerShell 7+ 默认即 UTF-8，无需包装。）

⚠️ **反向教训（同一处踩到）**：首版包装把**参数名也加了引号**（`'-Yes' '-Python'`）——
PowerShell 里那是**字符串字面量**，于是 `param()` 绑定退化成位置绑定，
实测 `$Platform` 被赋成 `-Python`。已固化为
`upstream/tests/test_install_scripts.py::_ps_arg()`：**参数名原样、值才引用**。

⚠️ 同族：`subprocess(text=True)` 不带 `encoding=` 会按 `locale.getpreferredencoding()`
解码，中文 Windows 上是 GBK —— 两个方向都会炸，故「只设 `PYTHONUTF8=1`」压不住。
