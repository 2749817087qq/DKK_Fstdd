## 现象

macOS 上用 venv（Python 3.13.12）执行 `./install.sh` 安装全部 PASS：

```
[3/4] 生成 skill → 7 个 skill [OK]，安全策略 [PASS]
[4/4] 校验 → verify_workbuddy_skills 全部 [PASS]
```

但运行新增的 `verify_skill_standards.py`：

```
[FAIL] TC-SES-001  校验实际执行 CLI — verify 执行失败（退出码 1）
[FAIL] TC-SES-004  --fix 完整性与安全性 — --fix 执行失败（退出码 1）
[FAIL] TC-SES-005  生成 skill 天生合规 — 6 项不合规：fstdd~fstdd-upgrade 全部「缺失」
[FAIL] TC-SES-007  无假失败 — 真实环境 verify 失败（退出码 1）
结果：3/7 通过
```

而 `verify_workbuddy_skills.py`（6 skill + CLI 冒烟）全部 PASS，`verify_rename.py` 5/5 PASS。

## 根因

新版本 spec `install-source-single` SC-001 引入「法定源」概念：

| 角色 | 路径 | 说明 |
|---|---|---|
| 法定源（权威） | `~/.workbuddy-ai/Fstdd` | git 仓库，HEAD=工作区，有 tag fstdd-v1.0.0 |
| 工作区（开发副本） | 当前 clone 目录 | 开发用 |
| GitHub（上传目标） | 2749817087qq/DKK_Fstdd | 分发用 |

`verify_skill_standards.py` 的安装位置解析改为「法定源优先」，但 `install.sh` 不创建法定源——
法定源不存在时，脚本从法定源解析 skill 目录失败，报 6 项 skill「缺失」。

## 修复建议

install.sh 应增加法定源创建步骤，或在 verify_skill_standards 中法定源不存在时降级解析而非报 FAIL。
