节点 FSTDD（本仓）实测证据（2026-10-06，change 2026-10-06-legacy-debt-cleanup）：

为建立「文本模式子进程必须声明 `encoding=`」的机器可验证契约，写了 AST 审计脚本，
扫描 `upstream/tests/`、`tests/`、`tools/` 三目录，结论「36 处 → 0 处，全绿」。
补完 36 处后审计脚本报 **0 违规**，根 `tests/` 与 `upstream/tests` 全量双双全绿。

但该脚本把 `subprocess` 模块名**写死为字面量**：

```python
if not (isinstance(func.value, ast.Name) and func.value.id == "subprocess"):
    continue
```

⇒ `upstream/tests/commands/test_new_isolate.py` 用 `import subprocess as _sp`（L43），
其 L96 / L144 两处 `_sp.run(..., text=True)` **完全没被扫到**。
补完后**再扫一遍**（已支持别名）仍然报「0 违规」是因为那两处已被人为补上 ——
若当初漏补，这个审计器会一直报绿灯。

**判据（可复用）**：审计脚本报「0 命中」时，不能只问「是不是真干净了」，
还要问「**如果我故意放一个违例进去，它抓得到吗**」。落地做法：审计器自带自检测试，
构造含**变体写法**（别名 import、`from X import Y as Z`、包装函数）的最小违例样本，
断言「能抓到」；再构造合法样本断言「不误报」。
本仓已固化为
`tests/test_subprocess_encoding_policy.py::test_scanner_binding_selfcheck`
与 `tests/test_release_manifest_accuracy.py::test_tc_rta_001e_false_claim_detector_is_not_vacuous`。

⚠️ 同族：`test_release_manifest_accuracy.py` 首版用固定子串清单做文档失真检测，
被独立评审用两个反例同时证伪 —— 漏判变体（假绿）与误杀「引述并更正」语境（假红）。
**审计器自身的假绿与假红都必须被拦住。**
