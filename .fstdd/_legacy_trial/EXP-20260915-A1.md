## 现象

在需要 SSH 隧道出网的环境下（`https_proxy=socks5h://127.0.0.1:PORT`）：

- `git clone` / `git push` **正常**
- 用 `urllib` 调 GitHub API（如 `GET /user`）→ `Remote end closed connection without response`

## 根因

| 组件 | socks5 支持 |
|---|---|
| git（libcurl） | ✅ 原生支持 |
| Python urllib | ❌ 只认 http/https 代理 |

两者对代理的理解不一致，造成「git 通、API 不通」。

## 处理

原设计是「先查身份再决定路径」：

```
GET /user → 拿 login → 判断是否仓库所有者 → 直推 or fork+PR
```

在隧道环境下这一步必然失败，**所有人都会被误判成外部贡献者**。

改为「尝试 + 降级」：

```
1. 先尝试 git 直推（走代理没问题）
2. 失败且错误信息含 403/denied/permission → 降级 fork + PR
3. 其他失败（网络）→ 如实报错，提示重试
```

## 性质

这是**依赖选择的坑**，不是实现缺陷。教训：当主路径用 git、辅助路径用 HTTP 库时，
必须确认两者对代理/证书/重定向的处理一致，否则会出现难以定位的分裂行为。
