## 现象

同一类失败，三种表现：

| 场景 | 报错 |
|---|---|
| `git -C "/c/Users/My Dir/repo" status` | `cannot change to '/c/Users/My Dir/repo': No such file or directory` |
| Python 收到 `/c/Users/...` | `can't open file 'C:\c\Users\...'` |
| `git remote add local /c/Users/.../repo.git` | `does not appear to be a git repository` |

## 根因

Git Bash 的路径体系（`/c/Users/...`）与 Windows 原生程序（`C:\Users\...`）不同。
传递时若不做转换：

- `git -C` 对含空格的 POSIX 路径处理有 bug
- Python 把 `/c/Users/...` 当作"当前盘符下的相对路径"，拼成 `C:/c/Users/...`

## 处理

```bash
# 路径转换（供传给 Windows 原生程序）
_winpath() {
  if command -v cygpath >/dev/null 2>&1; then cygpath -m "$1"; else printf '%s' "$1"; fi
}
SCRIPT_DIR="$(_winpath "$(cd "$(dirname "$0")" && pwd)")"

# 不要用 git -C，改为先 cd
cd "$REPO_DIR" && git status
```

## 性质

这是**跨平台边界问题**，在纯 Linux/macOS 环境不会出现，在纯 CMD/PowerShell 也不会出现——
只在 Git Bash 这类"POSIX 外壳 + Windows 程序"的混合环境暴露。

本项目实际踩了 **3 次**（推送脚本、安装脚本、验证脚本各一次），说明必须形成固定写法而非逐次排查。
