## 一、测试策略

### 1.1 测试金字塔

本变更是**环境与工具链治理**，被测对象不是应用逻辑，而是「位置与权威关系」：

- **集成层（主体，约 12 例）**：以 git 状态、文件内容、脚本输出为被测对象。
- **E2E 层（约 3 例）**：真实双向同步探针、真实重装、真实校验全绿。
- **单元层（约 2 例）**：安装位置解析顺序、配置字段读取。

### 1.2 测试原则

- **禁止只测「应该可以」**：同步通道必须用**真实探针**验证（提交→推送→目标工作区出现→回滚），
  而不是断言配置项存在。
- **只读断言**：对 `D:/Programs/DKK_Fstdd` **只做哈希比对**，不得写入。
- **反向验证**：凡「不依赖 X」的断言，必须**让 X 不可见后重跑**，否则无法证明独立性。
- **变异验证必做**：本次多为配置/文本断言，极易空转。
- **幂等性**：同步与重装都应可重复执行。
