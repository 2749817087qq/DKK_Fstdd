# 追加 8 类金融特有失败模式到 BUILD C4 — 技术设计

## Context

`.fstdd/skills/build.md` C4 section（L317-332）有 14 类通用失败模式 Markdown table，4 列（# | 失败模式 | 覆盖方式 | BUILD 检查动作）。零金融条目。

fstdd-fin SKILL.md 已定义 8 类金融特有失败模式（重复扣款/账实不符/静默降级/精度丢失/审计缺口/状态机漏洞/额度穿透/合规遗漏），但不进入通用 BUILD C4 检查清单。

## Decisions

### 1. 追加位置：L332（第 14 类）后面，同一 table 内部

**方案**：直接在现有 Markdown table 里追加 8 行（编号 15-22），不改 table header 和分隔线

**为什么**：保持同一检查清单，Agent 勾选项时金融模式和通用模式同屏可见，不分散

**备选排除**：新建独立金融 section → Agent 容易漏看；新建单独文件 → 增加维护负担

### 2. 编号：15-22

**方案**：紧接 14 类之后

**为什么**：编号隐含强制检查顺序（通用先过，金融后过）

### 3. 8 类金融模式内容来源

**方案**：取自 fstdd-fin SKILL.md L120-165，每类具体化为"覆盖方式 + BUILD 检查动作"

**为什么**：fstdd-fin SKILL.md 定义了名字和简述，本 change 补 BUILD 阶段可执行的检查动作

## Architecture

纯文档追加，零代码零配置零架构变化。

```
现有 table (14 行)           追加后 table (22 行)
  | ...                        | ...
  | 14 | 循环依赖...            | 14 | 循环依赖...
  +--------------------------  |----|----|------|----|
                              | 15 | 重复扣款...
                              | 16 | 账实不符...
                              | ...
                              | 22 | 合规遗漏...
                              +----------------------
```

## Risks

| 风险 | 缓解 |
|------|------|
| Markdown table 对齐破坏 | Edit 工具精确替换，保持 `| # |` 格式一致 |
| 8 类描述模糊 Agent 漏勾 | 每类检查动作必须写具体可执行步骤 |
