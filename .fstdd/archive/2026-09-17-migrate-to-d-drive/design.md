**C 盘系统重装 = 全部丢失。** D 盘是数据盘，不随系统重装。

上一轮 change（`canonical-in-workspace`）把法定源定在**工作区内**（C 盘），

## Decisions

### 1. 复制整个工作区，而非只搬仓库

**方案**：把 `stdd-repo/`、`backups/`、`.workbuddy-ai/`、根文件整体复制到
`D:/tools/FSTDD/`，保持同名同结构。

**为什么**：D哥 说「**整体**复制到 `D:/tools/FSTDD`」，且目标是「防资料丢失」——
`backups/`（2954 文件，含多轮归档与全量备份）与 `.workbuddy-ai/`（项目记忆）
同样是不可再生的资产，只搬仓库达不到防丢失目的。

**备选方案及排除原因**：
- 备选 A：只把 `stdd-repo` 放到 `D:/tools/FSTDD/` 根 → 排除。`backups/` 与记忆仍留在 C 盘，
  防丢失目标只完成一半。
- 备选 B：在 D 盘只建 git 仓库、靠 git 恢复 → 排除。git 不含 `backups/`、
  `.workbuddy-ai/`、`inbox/` 等（多为 gitignored），且本地未推送的备份会丢。

### 2. 用「复制」而非「移动」，C 盘保留

**方案**：复制完成后 C 盘工作区**原样保留**。

**为什么**：D哥 明确「先归档到本文件夹再复制到 D 盘」——C 盘是归档，D 盘是今后开发地。
且迁移期若有遗漏，C 盘是最后一道保险。删除是不可逆的，而 C 盘占用的空间不是瓶颈。

**备选方案及排除原因**：
- 备选 A：迁移后删除 C 盘 → 排除。D哥 未要求删除；且验证需要时间，
  过早删除会失去对照。

### 3. 复制后立即做三重验证

**方案**：① 文件数一致 ② **逐文件哈希一致** ③ git 状态（HEAD/tag/remote/clean）一致。

**为什么**：文件数一致**不足以**证明完整（曾有同名不同内容的情况）。
逐文件哈希是唯一可靠的完整性证据。git 状态则保证历史与 tag 未损。

### 4. 先验证 D 盘环境自洽，再重装 skill

**方案**：顺序为「复制 → 验证 → 从 D 盘跑三项校验 + 全量测试 → 重装 skill → 验证 skill 路径」。

**为什么**：若 D 盘环境本身有问题就重装 skill，会把 skill 指向一个坏环境，
排查时多一层干扰。先证明 D 盘能独立跑通，再让 skill 指向它。

### 5. 校验脚本无需改动（自适配）

**方案**：不改 `verify_*.py` 的路径逻辑。

**为什么**：它们基于 `__file__` 解析自身位置（自定位），迁移到 D 盘后自动指向 D 盘。
**这正是上一轮把顺序改成「自定位优先」的价值兑现** —— 若当初硬编码 C 盘路径，
本次迁移就得再改一遍代码。

### 6. 文档与记忆同步，并保留既有告警

**方案**：更新第 0 节与 `MEMORY.md`；**保留**「`D:/Programs/DKK_Fstdd` 不要动」
与「GitHub 是上传目标」两条。

**为什么**：文档是位置判断的依据来源。但更新时**不能顺手删掉仍然有效的历史告警** ——
D 盘调试副本与我们的仓库同名不同用途，这个坑极易再踩。

## Architecture

```
  ┌─ D:/tools/FSTDD/ ────────────────────────────┐   ← 今后开发根（数据盘，不怕重装）
  │  stdd-repo/      ← **新法定源**（git 仓库）    │
  │  backups/  .workbuddy-ai/  push_stdd_repo.sh │
  └──────────────────────────────────────────────┘
                    │ 安装
                    ▼
        ~/.workbuddy/skills/fstdd*  （路径指向 D 盘）

  ┌─ C:\Users\Administrator\WorkBuddy AI\2026-…\ ─┐
  │  保留（历史归档），不再开发                      │
  └───────────────────────────────────────────────┘

  ⚠️ D:/Programs/DKK_Fstdd  —— 另一程序的调试副本，全程只读
  ⚠️ ~/.workbuddy-ai/Fstdd  —— 上一轮已归档，保留
```

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| **复制不完整**（最关键的不可逆风险） | 文件数 + **逐文件哈希** + git 状态三重验证；C 盘保留作对照 |
| 复制中途失败留下半成品 | 先复制到目标、验证通过后才重装 skill；失败可重跑（复制是幂等的） |
| D 盘环境跑不通，却已重装 skill | Decision 4：先验证 D 盘自洽，再重装 |
| 误动 `D:/Programs/DKK_Fstdd` | 全程只读；同名不同用途，文档与记忆保留告警 |
| 更新文档时误删仍有效的告警 | Decision 6 明确要求保留两条既有告警 |
| 迁移后 C/D 两份并存又漂移 | 明确 **D 盘为唯一开发地**，C 盘仅归档（不再写入）；文档写明 |
| 长路径 / 中文路径在 D 盘的问题 | 目标路径 `D:/tools/FSTDD` 全为 ASCII，无中文无空格 |
