# FSTDD 新节点接入规程

> 适用版本：FSTDD 3.0.x+
> 最后更新：2026-09-25
> 来源：`notices/00-ONBOARDING-CHECKLIST.md`（v1.0，据 FSTDD009 实战固化）

## 四阶段

### A · 准备（K/D哥）
1. 确认编号 / 联系人 / 机器系统 / SSH 能力
2. **发 token**：本地生成明文 → **只把 `sha256` 写进 `tokens.json` 的 `tokens[]`**（先备份；服务按 mtime 热加载，无需重启）
   ⚠️ **发放的必须就是登记的那一枚**（否则节点必然 401）
3. **生成节点专用 SSH 密钥**（**不要扩散共用部署私钥**——共用键无法单独撤销）
4. 建 `notices/<节点>/`（755）
5. 放接入材料（接入指引 / 下载 fstdd 指引 / 密钥交接 / 取件提醒）
6. 登记 state + `CHANGELOG-ops`

### B · 发前自检（必须）
- **token 验证**：正确 token + 空 body → **422**（鉴权过）；错误 token → **401**
- **clone 路径验证**：克隆到临时目录，核对 HEAD / 经验件数 / 图谱节点数 / 模板数
- **权限**：敏感件 600、属主 ubuntu

### C · 节点执行
`C1` 拿三样（地址/token/密钥）→ `C2` ssh 连通 → `C3` **取敏感件并立即删服务器副本** →
`C4` **拉 fstdd 本体** → `C5` 投递自检（health 200 + POST 200）→ `C6` 读配套必读 → `C7` 回执三份

### D · K 验收
收齐回执并**核内容**（字节量+关键字段+原始输出，**不只看文件存在**）→ 确认服务器副本已删 → 登记 → 纳入常规

## 十坑（实测）

1. token 不同源 → 401（发放必须=登记）
2. 私钥/token 留服务器 → 钥匙插门上（取后即删；24h 回收）
3. **首次取件的循环依赖** → 必须先有一次带外
4. 共用私钥无法单独撤销 → 用专用密钥
5. 中文文件名跨编码层被吃 → 跨机文件名纯 ASCII
6. **Windows 文件名不能含冒号** → 静默失败
7. **命令回显 ≠ 结果** → 一律 `ls`/读回验证
8. `sudo` 写后属主变 root → 用 ubuntu 身份写
9. 旧地址残留 → 统一 HTTPS 端点
10. 凭证明文入回执 → 明令禁止
