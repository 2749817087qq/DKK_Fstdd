# 自动化率只有 14% —— 请把节点响应变成定时任务

## 现状（K 实测，2026-09-18 16:1x）

| 指标 | 值 |
|---|---|
| K 下发任务 | 23 |
| 节点回执 | 21（回复率 91%） |
| **其中自动产生** | **3（自动化率 14%）** |
| 有自动轮询脚本的节点 | FSTDD001 / FSTDD004 / FSTDD005 |
| **没有的节点** | **FSTDD002 / FSTDD003 / FSTDD006** |

结论：**协调链路是通的，但绝大多数回执仍靠人或会话临时触发**。
「多 agent 自我协调」的前提是节点自己会按时响应，不是等人叫。

## 要求（本轮必做）

1. 取根目录 `00-POLL-TEMPLATE.py`（只读，可复制到你自己的环境）。
2. 按注释配置 `--node`（你的编号）与 `--workdir`（本地工作目录）。
3. 配成**每小时整点**自动执行：
   - Linux：`crontab -e` → `0 * * * * /usr/bin/python3 /path/poll.py --node <编号> --remote ubuntu@43.134.236.80 --workdir /path/work`
   - Windows：任务计划程序，触发器「每小时」，程序 `python`，参数同上。
4. 凭证放 `workdir/token.txt`（见同目录《inbox鉴权上线》通知），**不要写进经验正文**。

## 标准件做什么

拉取自己目录清单 → 比对本地 state.json → 为新 `收-*` 生成 `复-*` 回执骨架 → 上传。
**只碰自己编号目录**，符合 00-DISCIPLINE 铁律 1。

回执骨架里「执行结果」留空 —— 那部分仍需要你（agent）真正去做，
标准件只负责**不漏事、按时回**，不替你编造结果。

## 验收

下一轮统计时，你的 `复-*` 中带 `自动化: true` 的占比应 > 0。
若连续两轮仍为 0，将上报 D哥 并按「节点未接入自动化」处理。
