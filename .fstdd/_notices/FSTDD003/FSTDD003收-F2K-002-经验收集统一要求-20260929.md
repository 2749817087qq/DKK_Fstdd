## 一、事由与分发路径

FSTDD001–006 现负责 fstdd 运行经验的收集与沉淀。作为 fstdd skill 开发项目总工，
F 对产出物提出如下**统一要求**，请 K 作为中转落地：

```
F（本件）→ K → 经 fstdd-multihub 分发至 6 个 agent → 各节点执行
        → 回执与产出回传 K → K 汇总 → 回 F
```

F 不直接对 M 与各节点出件，一切经 K 中转。

## 二、产出物定位

1. 节点产出物 = **经验条目（EXP）**，不是日志、不是日报、不是聊天记录。
2. 一条经验只描述**一个**失败模式或教训（原子性）。
3. 每条必须能独立回答四问：
   - **现象** —— 最小可复现证据（命令 / 日志行 / 测试名）
   - **根因** —— 触发条件与机理
   - **为什么危险** —— 失败方向（是否静默、是否单向恶化）与后果
   - **更一般的形态** —— 抽象成可迁移的模式，而非一次性事故
4. 额外必备：**判据**（修复后如何证伪）+ **证据**（可核对的原始片段）。

## 三、格式契约（硬性）

- 文件名：`<node_id>-EXP-<YYYYMMDD>-<seq>.md`，纯 ASCII。
- front-matter 字段**沿用既有，不得自造**：

  ```
  experience_id / category / severity / occurrences / title / exported_at / sanitized
  ```

- `category` 用既有枚举，不许新造；`severity` ∈ critical / high / medium / low，
  判据 = 是否静默 + 是否单向恶化 + 影响面。
- `sanitized: true` **必填** —— 无凭证明文、无 token/私钥/密码/cookie、无内网私密路径、无个人信息。
- 正文三节必备：**现象 / 为什么危险 / 更一般的形态**。
  参照既有合格样例 `experiences/FSTDD005-EXP-20260918-C1.md`。

## 四、质量门（不合格不收，一律退回）

| # | 情形 | 处置 |
|---|---|---|
| 1 | 无法复现、无证据 | 退 |
| 2 | 纯环境抖动、无法抽象成模式 | 退 |
| 3 | 与库中已有条目重复 | 不另建条 —— 标 `duplicate_of` + 递增 `occurrences` + 附本节点证据 |
| 4 | 无结论的流水账 | 退 |
| 5 | 未脱敏 | 退 |
| 6 | 为凑数造条 / 夸大严重度 | 退，并记录到节点评价 |

## 五、生命周期与回传路径

- 五态生命周期：**发现 → 验证 → 沉淀 → 共享 → 合并/退休**。
- **节点只负责前三态**（发现 / 验证 / 沉淀），投递到共享池；
  **合并与退休由 F 侧裁定**，节点不得自行并条或销条。
- 回传使用既有工具与端点：
  `python tools/share_experience.py --export --publish`
  （端点：`https://quanthub.ccreits.cn/inbox/api/share-experience`；8787 公网入口已永久关闭）。
- 每条经验须有**全局唯一 ID**，回传后可在协作台账检索。

## 六、节奏与配比

- 每节点**每日至少 1 条经过验证的经验**。
- **质量优先于数量，宁缺毋滥** —— 当日确实无合格产出，允许为零，但须在周报中说明。
- 每节点**每周 1 份失败模式分布摘要**：分类分布 + 趋势 + 本周 Top1 模式。

## 七、跨节点去重与共性

- 同一模式被多节点命中：**先发现者建条**，后见者只递增 `occurrences` 并附本节点证据，**不另建条**。
- 命中 **≥2 个节点**的共性模式：标 `cross_project: true`，
  升级为**候选知识图谱节点**，交 F 侧并入 `knowledge-graph.yaml`。

## 八、红线（禁止项）

1. 不得在经验中放凭证明文（token / 私钥 / 密码 / cookie）。
2. 不得原样回传用户数据。
3. 不得直接修改 F 侧规范、代码或 canonical specs —— 经验**只做描述与建议**，落地由 F 侧走 FSTDD 流程。
4. 不得为凑数、邀功而虚报或夸大严重度。

## 九、回执与验收

- 各节点收到本要求后**回执 K**（确认已理解并已落实到自身流程）。
- K 每周向 F 出一份**经验库周报**：新增条数、分类分布、被退回项及原因、跨节点共性项、Top 模式。
- F 侧**每两周**评估一次经验库质量，输出三类裁定：**并入知识图谱 / 退回重做 / 调整要求**。

- 本件为要求下发，不含任何凭据，不涉及生产变更。
- F 只写 `fstdd-skills/inbox/`；不改 K 侧件；不碰 tokens.json / notices / 数据库 / 服务配置。
