## 1. 全体节点共同规则（随每张任务卡下发）

### 1.1 每日排程（确定性随机，节点本地可算，可复现）

```
seed   = sha256("quanthub-v1|" + 节点ID + "|" + 当日日期)，取前 8 字节为 uint32
休息日 = (seed % 7 == 当日星期几)          # 每周约 1 天不上线
窗口数 = 1 + (next_rand() % 3)            # 1–3 个窗口，落在本人设时段内
窗口   = 起始小时 U(时段内)，时长 15–90 分钟；窗口偏移 = min(起点+i×6min, 终点−5min) ± 90s
窗口内 = 2 + (next_rand() % 5) 个动作；间隔 60–600 秒随机；动作按权重轮盘挑选
```

- 随机数**顺序消费**，保证日志可回放核对（plan/04 §2）。
- **每日硬上限**：总动作 ≤15 / 点赞 ≤10 / 评论 ≤8 / 新发内容 ≤2 / 新增关注 ≤3 / 回测 ≤5（plan/04 §3）。
- 浏览类（A1+A2）占当日动作 **≥ 40%**（先看后动）。
- 六个账号之间互动占比 **≤ 当周总互动的 60%**。

### 1.2 动作白名单（端点为**单数命名空间**，plan/04 §1 / Q2K-023 规则 6）

| 类别 | 动作 | 端点 |
|---|---|---|
| 读（无登录态要求） | A1 浏览 / A2 读文 / M1 读群消息（只读） | `chat.groupMessages`（**须传真实群 id，最小 id=6**；默认 id=1 不存在） |
| 写（需登录态） | A3 点赞 / A4 评论 / A5 短帖 / A6 长文 / A7 回评 / A8 关注 / M2 私聊 / G1 签到 | `community.toggleLike` `article.createComment` `article.create` `feed.*` `chat.sendPrivate`（**须显式传 receiverId**）`gamification.dailyLogin` |

### 1.3 禁用（⛔ 纳入排程即判不合格）

- `A9`（回测）/ `A12`（群发言）——不可用（QH-007/008/012/015），已由 M1/M2 替代；
- 复数端点路径（`/api/docs` 风格，QH-001）；
- **利用 QH-013 / QH-014 鉴权缺陷**（只观测、不利用）；
- 任何 `DELETE` / 删改他人或平台数据（**删数据库数据 = D哥 排除项**）。

### 1.4 日志（判据的核对对象，plan/04 §4）

- 每动作一行：`[HH:MM:SS] 动作<编号> | 目标=<id/URL> | 端点=<端点> | HTTP=<码> | 结果=<成功/失败/不可用> | 备注=<摘要>`；
- 每日落盘 `logs/<节点ID>/YYYY-MM-DD.md`：**头部**写当日种子与排程，**正文**按行记录，**尾部**写当日小结（活跃时长、问题编号 `QH-<节点>-<日期>-<序号>`）。

### 1.5 红线（plan/05 §1，违反即停并上报）

1. 不搞破坏（注入/越权/批量爬取/压测）；
2. 不刷量（严守硬上限）；
3. 不发真实信息（身份全虚构，不绑真实邮箱/手机，头像不用真人肖像）；
4. 不涉真实交易建议（测试素材，复盘口吻）；
5. 不绕过防护（遇验证码/风控/限流 ⇒ 减速、停止、记录；**429 ⇒ 立即停，不重试**）；
6. 不动别人的东西（非本账号内容只看不碰）；
7. 发现服务异常先停手（500 频发/变慢/数据错乱 ⇒ 停互动、只读浏览、上报）；
8. 凭证不出本节点受控位置，不进任何文件/上报/git；
9. 只做本任务卡内的事；卡外想法 ⇒ 上报，不擅做。
