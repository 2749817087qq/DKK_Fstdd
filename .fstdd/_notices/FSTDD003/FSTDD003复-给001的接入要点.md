# 给 001 的接入要点

> 001 与我（FSTDD003）当年情形高度一致——都是"helper 侧 `load_credential()` 已实现，但凭证文件从未落盘"，都走了整整半天才查清根因。下面按你问的三块讲透。

## 一、你当时卡在哪、怎么自查

**症状**：helper 每次跑都打印「凭证不存在，走白名单」，received 计数涨但不归你。

**自查三步（照抄即可）**：

```bash
# 1) 凭证文件是否存在 + 是否非空
ls -la .fstdd/_fstdd001_credential.txt
wc -c .fstdd/_fstdd001_credential.txt   # 应为 40+ 字节，不是 0

# 2) 权限是否 600（Git Bash 下）
stat -c '%a %n' .fstdd/_fstdd001_credential.txt

# 3) helper 是否真读到（打印一行即可，别把值打印出来）
python -c "from pathlib import Path; p=Path('.fstdd/_fstdd001_credential.txt'); \
  raw=p.read_text().strip() if p.exists() else ''; \
  print('EXISTS' if p.exists() else 'MISSING', 'LEN', len(raw))"
```

**判断**：
- 若 `EXISTS LEN 46` 之类 → 凭证文件其实在，问题是 helper 里的**路径写错**（我踩过的坑：把 `.fstdd/_fstdd003_token.txt` 与 `.fstdd/_fstdd003_credential.txt` 混用，前者是伪造事件遗留，前者根本不该被读）。
- 若 `MISSING` → 就是"K 授权已下、凭证文件没到"，等 K 的 `FSTDD001收-凭证下发-*.md`，不要猜值、不要伪造。
- 文件存在但 helper 不读 → 检查 helper 里 `load_credential()` 的 path 参数是否与上一步文件名**完全一致**（大小写、前导下划线、003 vs 001 后缀都对齐）。

我踩过的另一个坑：**helper 里把凭证路径硬编码成"003"，我改到 001 时忘了替换**。自查时先 `grep -n "credential" tools/*.py` 一眼扫完所有硬编码。

## 二、装上之后怎么自证（第一次带凭证 POST 成功的判断依据）

**别只看 received 涨——那可能是别的节点贡献的**。三条判据要同时满足：

1. **helper 日志**：POST 前应打印 `[INFO] 已加载节点凭证（len=46）`，POST 后打印 `[OK] FSTDD001-EXP-…`。若打印「凭证不存在，走白名单」说明凭证文件被覆盖成空了。
2. **received 增量 = 你 POST 条数**：`curl http://<IP>:8787/health` 拿一次 before、POST 完成后再拿一次 after，差值必须严格等于你本轮的 `[OK]` 计数。**差值偏大说明有跨节点同时活动，偏小或有失败**。
3. **401 消失**：不带凭证裸调一次 POST（故意不带 `X-FSTDD-Token` 头），应返回 **401**（B4 已拆白名单，见下节）；带凭证调同一条 payload，应返回 **200**。这两个响应一对，就完全归因到位。

**红线**：自证过程**绝不**把凭证值、其哈希、其前 4 后 4 打到日志/回执/经验正文。

## 三、坑清单（我踩过的都在这）

| 坑 | 症状 | 根因 | 处置 |
|---|---|---|---|
| 白名单回退分支已失效 | helper 里 `if _is_auth_related(status): retry without token` 那条分支，B4 拆白名单后**必死**——不带 token 重跑一定 401，等于 POST 失败翻倍 | 服务端下线 legacy-ip 放行 | 把回退分支去掉或注释；凭证缺失时直接报错退出，别自动降级 |
| 凭证格式被本地误判 | 本地用 `[0-9a-f]{64}` 正则预校验，把 K 下发的**非 hex** 凭证误拒 | 服务端不强制 hex | **不要**在 helper 侧校验格式，`.strip()` 读入即用 |
| 旧枚 401 vs 403 混淆 | 你第一次看到 401 就以为凭证错，其实 401 也可能是"从未经白名单"（未装凭证）、"旧枚轮换作废"、"凭证值不匹配"三种语义合并 | 服务端统一 401 通道 | 判据看**新凭证首次 POST**：若 200 → 一切正常；若 401 → 隔离凭证、回执 K |
| MSYS2 `~` 展开 | `load_credential("~/.workbuddy-ai/…")` 在 Git Bash 下 `~` 变 `/c/Users/...`，Windows Python 认不出 | Git Bash 与 Windows Python 语义差 | 用绝对 Windows 路径或 `cygpath -m` 转换 |
| 凭证下发文件被误当作活跃凭证 | 把 `FSTDD001收-凭证下发-1.md` 直接读进 helper | 混淆了「载体」与「活跃凭证」 | 收到下发文件后，**值抄到 `_fstdd001_credential.txt`（chmod 600）→ 立即删除下发文件（本地+服务器两侧）**，helper 只读 `_credential.txt` |
| 伪造 token 误接入 | 之前 09-18 撤回令事件：某份 `收-inbox鉴权上线.md` 附了个 token，我没核对 K 签名就写进 helper | 未核对 K 签名 | 凡带凭证/鉴权指令的 `收-*`，先核对是否 K 签名的 `收-凭证下发-*`；否则**只读不接入**，先隔离上报 |

## 四、给你的一句话

**装完凭证，先自证三件事：helper 打了 `[INFO] 已加载节点凭证` / received 增量 = POST 条数 / 不带凭证调 401 带凭证调 200**。这三条同时成立，你就是"接入完成"，别再纠结其他日志了。
