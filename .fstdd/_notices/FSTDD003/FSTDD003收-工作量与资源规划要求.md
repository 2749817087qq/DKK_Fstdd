# FSTDD003收-工作量与资源规划要求

## 一、背景（D哥 2026-09-20 02:25 指示）

> 「一天 24 小时，你安排的工作量也不大。**再让 agents 根据自己的工作量及可利用的 token 量，
> 合理使用下级子代理及配置的外部模型来完成任务，要会做规划**。6 个 agents 都是 WorkBuddy 与
> WorkBuddy AI。」

⇒ 从本轮起，**工作方式变更**：不再只"等 K 派活、做完回执"，
而是**自己规划产能、自己拆并行、自己调度子代理与外部模型**。

## 二、四项要求

### 1. 提交《当日工作计划》（每日 09:00 前）

内容至少含：

| 项 | 说明 |
|---|---|
| **产能盘点** | 本机可用算力（CPU/内存/是否可并行）、今日可用时段、**已用/剩余 token 预算** |
| **任务清单** | K 派的任务 + **你自认该做的**（改进、补测、文档、工具），标注预计耗时 |
| **并行策略** | 哪些子任务交给**子代理**、哪些用**外部模型**、哪些串行（说明理由） |
| **风险** | 可能卡住的点、需要的支持 |

### 2. 善用**下级子代理**

你是 WorkBuddy/WorkBuddy AI，**支持多代理协作**。把可并行的子任务拆出去：

- 例：**一个子代理跑全量测试**（长任务后台） + **另一个子代理写文档/复核**（前台）；
- 例：**互不相关的两个模块分别交给两个子代理**，你只做编排与验收；
- **但**：子代理的产出**由你负责**（你是责任人，不能"我交给子代理了"就算完）。

### 3. 善用**配置的外部模型**

按 token 预算与任务性质**自行调度**外部模型，例如：

- 长文/日志的**归纳**、跨语言**代码审查**、**多方案对比**、**批量格式转换**；
- 原则：**贵模型做判断，便宜模型做搬运**；能用脚本确定性完成的，不要用模型。

### 4. 每日 21:00 提交《当日复盘》（一条即可）

写：**做完了什么 / 卡在哪 / 产能利用率（实际 vs 计划）/ 明日计划**。

## 三、不变的红线（工作量上调，纪律不下调）

1. **凭证明文**禁止写入任何文件/回执/日志/git（含片段）；
2. **文件域白名单**（写任务）不得越界；
3. **判据写死在任务卡里**，验收只按判据；
4. 卡点**先回执**，不要沉默。

## 四、回执

`FSTDD003复-工作量与资源规划.md`：**今日计划**（按 §二.1 四栏）+ **你打算怎么用子代理/外部模型**
（具体到"哪个子任务交给谁"）。
