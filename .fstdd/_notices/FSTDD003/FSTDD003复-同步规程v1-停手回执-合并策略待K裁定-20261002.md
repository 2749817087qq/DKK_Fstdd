## 四、请 K 侧裁定的合并策略

当前 `_scratch/upstream-cli-sync/` 已是远程完整克隆（1175 files）。请 K 决定以下哪种策略：

| 策略 | 说明 | 风险 | 我这边要做什么 |
|---|---|---|---|
| **A. 本地仓库 reset 到远程** | 丢弃本地 167 commits，用远程 master 替换 | ⚠️ 高——本地所有变更丢失（闸门、daily_share 补丁、phase1 经验等） | `git reset --hard server/master` 但要先把本地改动 diff 出来作为 patch 单独提交 |
| **B. 用远程做 base，本地改动作为 patch layer** | 先 checkout 远程 master，再把本地 167 commits cherry-pick 或 rebase 上去 | 中——冲突多但可控（大部分冲突在 `.fstdd/`，本地改动主要在 `tools/`） | `git checkout -b upstream-base server/master` + `git cherry-pick` 本地独有 commits |
| **C. 先 sync upstream/ 和 specs/standards，本地其他不动** | 用 `git checkout server/master -- .fstdd/specs .fstdd/standards .fstdd/config.d` 逐目录合入（**不合并 git 历史**） | 低——不动 git 历史，只拉文件 | 直接 checkout 子目录 + diff 合并本地定制 |
| **D. 把 upstream CLI 子树 pip install 就够了，git 历史暂不动** | 我已经 pip install 好了，先用着；specs/standards/skills 按需从 `_scratch/upstream-cli-sync/` 手动拷贝 | 最低——不碰 git | 拷贝需要的目录，绕过 merge 问题 |

**我的建议：先 C 后 D。** 先把 specs/standards/config.d 这三个本地零改动或低改动的目录从远程合入（C 策略），解决"本地 specs 缺失"这个最直接的问题；CLI 已经 pip install 好了（D 策略已执行）。git 历史层面的合并（A/B）等到 phase 同步机制落地后再做。
