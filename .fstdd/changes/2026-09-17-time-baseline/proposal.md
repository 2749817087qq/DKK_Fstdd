# 时间基线：让每份产出都能回答「何时、基于什么状态」

## Why

FSTDD 的产出**无法回答两个基本问题**：「这条信息是什么时候采集的？」「它基于哪个代码/数据版本？」

这不是理论担忧 —— 在 D哥 指出后做了全仓实测，**九个相关词在宪法里全部零命中**：

  | 检索词 | 宪法 `FSTDD_CONSTITUTION.md` 命中数 |
  |---|---|
  | 时间 / 时效 / 基线 / 新鲜 / 时钟 / 时间戳 / 时刻 / timestamp / 过期 | **0（全部）** |

具体缺口有六处，每一处都有实测证据（见 evidence）：

  1. **没有"时间基线"这个概念** —— 流程里没有任何一处要求记录或校验时间
  2. **时间戳格式三种形态并存，且多数不带时区** → 跨机协作时无法排序、无法比较
  3. **"生成时刻"冒充"采集时刻"** —— `generated_at` 是渲染时刻，与信息实际采集时刻无关
  4. **没有代码/数据版本锚点** —— 只有"被分派的任务"才有 `base_git_sha`，
     **本地发起的 change 完全没有**；`git log` 与产物之间没有可追溯的连接
  5. **证据不带观测时刻** —— `why.evidence` 写着"只读巡检实测"，却没写**何时**测的，
     无法判断证据是否已过期
  6. **跨机时钟无法验证** —— 实测本机 ↔ 服务器单次往返 5.5–6.2s，连"两台机器的时钟
     是否一致"都无法在秒级上确认；3 台机器中的另外 2 台**从本机完全不可达**

危害是**静默的**：所有产物看上去都有时间戳，所以没人会觉得缺什么；
但真到需要判断"这份证据还成立吗""这个结论是基于哪个提交得出的"时，答案并不存在。
对 6 个 agent / 3 台机器的协作而言，"谁在什么时候基于什么说的"是协作的**最低前提**。


## What Changes

- 【基线契约】为每个 change 定义显式时间基线：`baseline.at`（基线时刻）、
`baseline.base_git_sha`（代码版本锚点）、`baseline.node_id`（在哪个节点建立）、
`baseline.clock_source`（时间取自哪里）。写入 `.fstdd.yaml`，
使"本地发起的 change"也拥有与被分派任务同等的基线。

- 【统一时间戳规范】全仓时间戳统一为**带时区的 ISO 8601**（UTC 或显式 offset），
禁止 naive 时间戳。CLI 与控制面采用同一规范，使两者时间可直接比较与排序。

- 【证据时效标注】`why.evidence` / spec 的 `evidence` / test-report 的证据条目
必须带 `observed_at`（观测时刻）与观测时的 `base_git_sha`，
使"这份证据还成立吗"成为可判定问题，而不是靠印象。

- 【产物头部基线块】产物头部同时呈现三个**不同**的时刻：
`created_at`（信息采集）/ `generated_at`（渲染）/ `baseline.at`（基线建立），
并附 `base_git_sha`，消除"渲染时刻冒充采集时刻"。

- 【时钟对齐巡检】提供一条命令报告各节点与本机的时钟偏差，
并给出**三态判定**：偏差可接受 / 偏差超限 / **无法测量**（如 RTT 抖动过大、
节点不可达）。三态必须可区分 —— 否则会把"测不准"误报成"已对齐"。

- 【宪法条款】在 `FSTDD_CONSTITUTION.md` 中增加时间基线条款，
并让 Gate 检查引用它，使"记录时间基线"从"好习惯"变成**强制契约**。

- 【模板同步】`proposal` / `design` / `spec` / `test-plan` / `test-report` 模板
同步加上基线字段与观测时刻字段，使新 change 默认即符合规范。

- 【DC-HASH 耦合】`canon verify` 的源哈希改为**对归一后的内容**哈希
（先做 EOL 归一再哈希），使"时间字段变更 / 行尾归一"不再导致双轨校验误报失败。


### New Capabilities

- **时间基线契约**：每个 change 都有显式基线（时刻 + 代码版本 + 节点 + 时间来源），
本地发起的 change 不再是没有基线的二等公民。

- **统一时间戳规范**：全仓时间戳为带时区的 ISO 8601，CLI 与控制面一致；
naive 时间戳成为可被静态检查发现的错误。

- **证据时效标注**：证据条目带观测时刻与观测时的代码版本，使证据"过期"成为可判定的事实。

- **时钟对齐巡检**：一条命令给出各节点时钟偏差与三态判定（可接受 / 超限 / 无法测量），
把"时钟是否对齐"从假设变成可验证的结论。


### Modified Capabilities

- **FSTDD 宪法**：增加时间基线条款，使基线记录成为 Gate 强制检查项，而非建议。

- **产物模板与 CLI**：模板默认携带基线字段；CLI 统一时间戳格式并新增基线检查命令。

- **canon 双轨校验**：`DC-HASH` 由「原始字节哈希」改为「EOL 归一后的内容哈希」，
解除与行尾治理的耦合。
