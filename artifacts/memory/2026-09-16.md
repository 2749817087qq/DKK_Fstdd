## ⭐ 机制定论修正（D哥 那边二次实证，取代我的旧结论）

我原先写"两个目录都会被扫描"——**不准确**。正确机制：

**加载目录 = 实例自己的 home + `skills/`，是按 home 拼装的相对路径，不是写死目录。**
`codebuddy.js` 里 `skills` 与 `agents/commands/hooks/output-styles/bin` 作为一组相对目录名
被遍历拼接 → 所以文件里 `.workbuddy-ai` 字面量 0 次仍能加载它。

本机并存**两个 WorkBuddy 实例 home**，各扫各的：
| 实例 home | skills 目录 | 谁在加载 |
|---|---|---|
| `~/.workbuddy` | `~/.workbuddy/skills`（63 个技能） | 日常实例（D哥 那边的会话） |
| `~/.workbuddy-ai` | `~/.workbuddy-ai/skills` | **本会话所属实例** |

推论：装到"另一个实例"的目录，本会话看不到——**不是没生效，是实例不同**。
判断方法：看会话技能列表里出现哪边独有的技能。
（我看到的 install-github-skill / stdd-hardening 属于 .workbuddy-ai，即本实例，所以观察成立。）

已据此把 install.sh 默认 OUT 改回 `~/.workbuddy/skills`（日常实例），
另一实例用 `FSTDD_OUT` 覆盖；本次用覆盖装到 `.workbuddy-ai`（D哥 指令，本实例）。
`install-github-skill` skill 里的旧说法已同步修正。
