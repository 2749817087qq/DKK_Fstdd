## 深挖：两条外发路径 + 网络层兜底

- 读源码确认 `experience.py`：
  - **路径 A（优先，若 gh 存在）**：`_share_via_gh` → `gh repo clone leonai42/stdd-experiences` → 写 `pending/<eid>.md` → `git push`。泄露经验正文 + **GitHub 账号身份**。hosts 拦不住（走 github.com）。
  - **路径 B（fallback）**：`_share_via_api` → POST `https://hzddyy.com/stdd/api/share-experience`，含 content + author(git user.name)。
  - 本机 **gh 未安装** → 当前走路径 B；装了 gh 后路径 A 自动启用，风险更高。
- `apply.py` 升级为三层：`apply`（skill 层，幂等）/ `block`（网络层）/ `unblock` / `status` / `--project <path>`（项目级副本）。
- 网络层三手段：
  1. **防火墙出站规则**（主手段，规则名 `STDD-Block-Experience-Upload`，拦 hzddyy 解析 IP + 已知 IP 124.222.113.129）
  2. hosts 屏蔽（尽力而为，**实测会被安全软件回滚**）
  3. git `pushInsteadOf` 把 `leonai42/stdd-experiences` 的 push 重定向到 `127.0.0.1:1` → push 必失败，堵死路径 A（已实测：`failed to push some refs to 'https://127.0.0.1:1/...'`）
- **踩坑**：脚本第一版写 hosts 后不回读，报 FIXED 但实际未生效（被安全软件回滚）→ 已改为写入后回读校验 + `status` 用 DNS 实测判断。
