## 现象

在 Windows 的 Git Bash 中：

```bash
pkill -f "ssh.*-D 18080"     # 报成功
netstat -ano | grep 18080    # 端口仍被占用
```

下次建隧道：`bind [<IP>]:18080: Address already in use`

## 根因

Git Bash 的 `pkill` 面向 POSIX 进程模型，无法匹配 Windows 原生进程（`ssh.exe`）。
它返回成功只是"没报错"，不代表杀掉了。

## 处理

用 OpenSSH 的 control socket（连接复用机制）：

```bash
# 建立（-M 开启 master，-S 指定 socket）
ssh -f -N -M -S /tmp/<DOMAIN> -D 18080 -o ExitOnForwardFailure=yes user@host

# 关闭（-O exit 通过 socket 通知主连接退出）
ssh -S /tmp/<DOMAIN> -O exit user@host
```

实测：建立后 `ssh -O exit` 能干净关闭，端口立即释放，无残留进程。

## 附带建议

- `ExitOnForwardFailure=yes`：端口冲突时立即失败，避免"以为建好了其实没建"
- 脚本里可加"自动找空闲端口"逻辑，作为端口被占的兜底
