## 现象

把 Python 包 `stdd` 改名为 `fstdd` 后：

- 39 个文件的静态 import 已全部替换
- `grep -rnE "^\s*(import|from)\s+stdd\b"` 返回**空**
- 但 `fstdd --help` 正常、`fstdd init` 崩溃：

```
File ".../fstdd/cli/__init__.py", line 483, in main
    mod = importlib.import_module(mod_path)
ModuleNotFoundError: No module named 'stdd'
```

## 根因

`cli/__init__.py` 里有一张命令映射表：

```python
commands = {
    "knowledge": "<DOMAIN>.cmd_knowledge",
    "bootcamp":  "<DOMAIN>.cmd_bootcamp",
    ...
}
mod_path, func_name = commands[<DOMAIN>].rsplit(".", 1)
mod = importlib.import_module(mod_path)
```

模块路径是**字符串**，不是 import 语句 —— 静态替换的盲区。

## 处理

补一条针对字符串字面量的替换：

```python
PAT = <DOMAIN>(r'(["\'])stdd\.cli\.')
new, n = <DOMAIN>(r'\<DOMAIN>.', text)   # 实测命中 34 处
```

## 一般化

**为什么 `--help` 通过而 `init` 失败**：`--help` 只走 argparse，不触发子命令的动态加载；
只有真正执行子命令才会 `import_module`。所以「顶层命令可用」不能证明「包改名成功」，
**必须跑至少一个真实子命令**。

这条也是「静态检查全绿 ≠ 运行时可用」的典型例子。
