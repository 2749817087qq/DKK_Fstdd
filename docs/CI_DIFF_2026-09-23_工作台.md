## 3. P46 —— `(d)` 把「ID 唯一性」实现成「字符串出现次数 == 1」

`ci.py:311-325`：

```python

unique = set(tc_ids)
```

## 4. P47 —— `stdd diff` 两条解析口径与项目约定不匹配

### ① TC 引用按连字符找，而 Python 函数名只能带下划线

`diff.py:45 / :70 / :102` 都用字面子串 `tc_id in file_content`，而 `tc_id` 形如 `TC-CP-111`。
**Python 标识符不能含连字符** ⇒ 测试函数名只能是 `def test_TC_CP_111_…`（下划线）
⇒ 覆盖率 **假 `0/19 (0%)`**。这是**语言约束造成的必然错配**，不是写法不规范。

**规避**：每条新用例的 docstring 首行另写一份连字符编号：
```python
def test_TC_CP_111_成功落盘_键是完整biz_原子写(self, monkeypatch, tmp_path):
    """TC-CP-111 / SC-001：以**完整 biz** 为键写 `list_pulled_at`；…"""
```

### ② 案例标题正则 `[\d.]+` 不接受字母

`diff.py:36`：`r"####\s+案例\s+[\d.]+\s*[—\-]\s*(.+)"`。
`案例 A.1`（按 capability 分组编号，很自然的组织方式）不以数字开头 ⇒ 全部解析不到
⇒ 直接 `未找到 TC 案例` 退出（`diff.py:56-58`）。
**规避**：改成 `案例 1.1` / `案例 2.1`（功能 A → 1.x、功能 B → 2.x，分组语义不变）。

### ③ 附带：「测试函数」列归属算法不可靠

`diff.py:104-114` 取「文件里**首次**出现该 TC-ID 的行，往上找最近的 `def test_`」。
TC-ID 常出现在类 docstring 的分组注释里（`"""…（TC-CP-111 ~ 116）…"""`）
⇒ 归属错位（实测 `TC-CP-111` 归到 `test_TC_CP_126_…`）。
**修好前只信覆盖率那一行。**

### ④ 实测：`ci` 与 `diff` 口径一致（不是互相矛盾的）

把 `tests/test_capture.py` 里全部 `TC-CP-1NN` 字面串临时改成 `TC_CP_1NN`，
跑完立刻按字节还原：

| 状态 | `ci` 的 TC 实现覆盖 | `stdd diff` 的覆盖率 |
|---|---|---|
| 带连字符编号（现状） | `✓ 19/19 (100%)` | `19/19 (100%)` |
| 只有下划线编号（项目原本写法） | `✗ 严重不足: 0/19 (0%)` | `0/19 (0%)` |

⇒ **两个工具会一起「看不见」，也会一起看见**。
⚠ 也正因为一致，**一次格式错配会让两条独立的质量信号同时失效**，没有交叉验证兜底。

## 5. P48 —— 一次性批量改写脚本「说成功但把文件改坏」

给 19 条 docstring 补连字符编号时，用 `re.sub` 回调批量改：

```python
def fix(m):
    tail = s[m.end(): m.end() + 400]
    newtail = re.sub(r'(""")(SC-)', r'\1TC-CP-111 / \2', tail, count=1)
    return m.group(0) + newtail        # 🔴 re.sub 只替换 m.group(0)，上下文被重复插入
```

脚本打印「已改写 19 处」、退出码 0，但：

```
pytest tests/test_capture.py -q   →  ERROR … 1 error during collection
ruff check --line-length 100 …    →  Found 741 errors          # 正常 21 条
文件行数                           →  1443 → 1621
```

🔴 **判别信号是「数量级」**：一次机械改写让静态检查从 21 涨到 **741**，
那不是「多了 20 个新问题」，是**文件结构被毁**。

**靠「改前 `cp` 到仓库外备份」在 30 秒内无损还原**（→ `116 passed`）。

## 7. 可复用结论（写给下一个用 FSTDD 的人）

1. 🔴 **SKIP ≠ PASS。** 看到 SKIP 先问「是**真的不需要**，还是**工具看不见**？」
   两种情形必须在报告里分开写；SKIP 的项一律**手工补做**。
2. 🔴 **别只看汇总的「0 错误」**，要看 **SKIP 数** 与 **检查项总数** 的比值。
3. 🔴 **TC-ID 在 test-plan 里只写一次**（定义行），交叉引用用**案例号**。
4. 🔴 **测试源码里必须出现「连字符」TC-ID**（docstring 里另写一份），
   否则 `diff`/`trace` 一起失明。
5. 🔴 **案例标题用 `1.x` 数字编号**，不要用 `A.x`。
6. 🔴 **机械改写脚本自带四项量纲校验**（命中处数 / 文件行数 / 静态检查条数 / 与备份 diff 行数），
   任一不符就停下来；改前 `cp` 到**仓库外**备份。
7. 🔴 **变异体必须 `compile()` 自检** —— 语法错的变异体会「全红」，被误读成「守卫咬住了」。
